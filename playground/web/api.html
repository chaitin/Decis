API reference

One endpoint does the work, and this page is served by the same origin that answers it. Below: what to send, what comes back, what the parameters and the limits mean, what each error says, and a box that sends a real request so you can watch a real answer arrive.

The endpoint POST /v1/systemone

Send JSON to POST /v1/systemone on this page's own origin. The playground serves these pages and forwards that one path to the engine: it attaches the bearer token in the request header, so the browser never holds one, and it rewrites the model field to the id of the engine that answered /readyz. JSON in, JSON out — there is no streaming endpoint.

Every response carries x-typesafe-request-id, error responses included, and the same id appears in the server log. It is what to quote when a call goes wrong.

The three primitives choice · score · noul

A question is one object with a type, the instructions the model reads, and criteria. All three types can be mixed in one request, and they are all judged against the same state.

choice

{
  "type": "choice",
  "instructions": "Which team should handle this?",
  "criteria": {
    "billing": "invoices, payments, refunds",
    "technical": "bugs, outages, system errors"
  }
}

choice picks one name from a set. criteria is an object, and its keys are the option names: the answer's choice is one of those keys, and the answer's probabilities has exactly the same keys in the same order.

score

{
  "type": "score",
  "instructions": "How urgent is this?",
  "criteria": ["no deadline", "this week", "today", "already late"]
}

score rates on an ordered rubric. criteria is an array from lowest to highest; in the answer, legend and probabilities use the string keys "0", "1", … and score is Σ k·pₖ over those 0-based levels, so a score can be fractional.

noul

{
  "type": "noul",
  "instructions": "Does the user threaten to cancel?"
}

noul is a yes/no question. The answer is a single scalar, noul = P(true), with no confidence and no probabilities. Its criteria is optional, and if you send it the keys must be exactly "true" and "false".

Three things hold on every response. choice equals argmax(probabilities), and its keys match your criteria keys in order. answers has exactly the same keys as questions. And those question keys are yours: they are never sent to the model, so two questions may be worded identically without being confused.

Engine limits

        

          Four limits belong to the engine rather than to the API, and each engine reports its own
          from GET /v1/models — a /v1/* path this playground does not proxy, so ask the engine
          directly. No values are printed here: the engine is the only thing that measures them.
        

        

          
            
FieldMeaning

          
          
            

              max_options
              Most criteria one choice question may have.
            

            

              max_question_tokens
              
                Token budget for one question, instructions and options included.
              
            

            

              max_sequence_tokens
              Token budget for state plus one question.
            

            

              max_state_tokens
              
                A separate budget for state alone, when the engine has one; 0 means the sequence
                limit is the only one.
              
            

          
        

        

          Token counts are measured with the engine's own tokenizer, not estimated from characters,
          and a request that does not fit is rejected rather than truncated. For scale: snake asks
          with 4 options, dino with 3 and tetris with 5. Those are examples of option counts, not
          limits.
        

      


      

        

          Errors
        

        

          Two body shapes exist, and a client has to handle both. Everything except validation
          answers with detail.error_type and detail.message; a validation or capacity failure
          answers with a list of loc / msg / type entries. The status codes below are the engine's.
        

        

          

            Everything except validation
            
{"detail": {"error_type": "authentication_error", "message": "…"}}

          

          

            Validation and capacity
            
{"detail": [{"loc": ["body", "questions", "move"], "msg": "…", "type": "…"}]}

          

        

        

          
            

              Status
              error_type
              When
            

          
          
            

              401
              authentication_error
              The bearer token is not valid.
            

            

              403
              authentication_error
              No credential, or a scheme other than Bearer.
            

            

              404
              —
              Unknown path.
            

            

              405
              —
              Known path, wrong method.
            

            

              413
              request_too_large
              Body over the engine's DECIS_MAX_REQUEST_BYTES.
            

            

              422
              —
              
                Bad shape, or a request the engine cannot honour: too many options, an over-long
                question, state over the budget, an empty criteria, an unknown model. The message
                names the measured number and the limit.
              
            

            

              429
              rate_limit_error
              
                Waiting for the engine exceeded DECIS_REQUEST_TIMEOUT_MS. Carries retry-after-ms.
              
            

            

              500
              engine_error
              The engine raised; the message includes the request id.
            

            

              503
              engine_unavailable
              The engine is not loaded, or its load failed.
            

          
        


        
This playground's own answers

        

          The proxy answers in the engine's shape, so one reader handles both, but these come from
          the playground itself.
        

        

          
            

              Status
              error_type
              When
            

          
          
            

              400
              invalid_request_error
              The body is not valid JSON, or not a JSON object.
            

            

              404
              not_found
              No such page, and no path the proxy answers.
            

            

              413
              invalid_request_error
              
                Larger than the proxy itself will buffer; it has its own cap, separate from the
                engine's.
              
            

            

              502
              upstream_error
              
                The engine could not be reached; the playground forgets its address and looks again.
              
            

            

              503
              searching
              
                /readyz while no engine is ready: it reports the candidates it is probing.
              
            

            

              503
              upstream_unavailable
              
                A POST to /v1/systemone while no engine is ready.
              
            

          
        

        

          Error responses carry x-typesafe-request-id too, and a 429 carries retry-after-ms so a
          retry can wait the right amount of time.
