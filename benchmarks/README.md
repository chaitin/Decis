# Benchmarks

Raw measurement output. **Documents and the README quote numbers from these files only** —
see [`AGENTS.md §8`](../AGENTS.md). A number that is not backed by a file here does not go in
the docs.

## Files

| File | Engine | Configs |
|---|---|---|
| `laya-multilingual-sweep.json` | `laya` @ `convaiinnovations/laya` subfolder `multilingual` | 24 (6 thread counts × 4 questions-per-request) |
| `laya-english-sweep.json` | `laya` @ `convaiinnovations/laya` (repo root) | 24 (same grid) |
| `kev-0.8b-cpu-dtype.json` | `kev` @ `jaredpalmer/kev-0.8b` | 2 (fp32 vs bf16 on CPU) |

## Host used for the pre-implementation measurements (2026-09-22)

```
aarch64 · 24 vCPU · 33.5 GB RAM · no GPU
Python 3.12.3 · torch 2.14.0+cpu · transformers 5.17.0 · laya 0.3.5
```

This host is deliberately the *worst case* for Decis: a CPU-only container with no
accelerator. Numbers from a GPU host are not comparable and must be recorded separately.

## Reproducing

The scripts that produced these files are in [`probe/`](probe/). They are pre-implementation
scaffolding: once `src/decis/` exists they are superseded by `decis bench`, but they are kept so
the numbers below can be re-derived.

```bash
# Laya: thread count x questions-per-request, raw per-config samples
PY=/path/to/venv/bin/python
$PY probe/probe_laya_sweep.py multilingual results/laya-multilingual-sweep.json
$PY probe/probe_laya_sweep.py ""           results/laya-english-sweep.json

# kev: fp32 vs bf16 on CPU, two server processes
KEV_SRC=/path/to/kev PY=$PY bash probe/run_kev_dtype.sh

# single-shot variants (one config, prints a compact summary)
$PY probe/probe_laya_single.py multilingual 10
$PY probe/probe_kev_http.py http://127.0.0.1:8010 10
```

Two environment gotchas these scripts exist to work around, both of which cost real debugging time:

1. A `no_proxy` value containing the IPv6 literal `[::1]` makes `httpx` raise
   `InvalidURL: Invalid port: ':1]'` while constructing its client — before any request is sent.
   `huggingface_hub` uses `httpx`, so every download fails. The scripts pin
   `NO_PROXY=127.0.0.1,localhost`.
2. `KEV_DTYPE` must be set per experiment. `bf16` on CPU is ~83× slower than `fp32` (see
   `kev-0.8b-cpu-dtype.json`), so a single unlabelled timing is worse than useless.

## Caveats

These are **methodological limits of the current data**. They are recorded here, not buried, because
the numbers are quoted in the docs and someone will eventually try to compare them. See
[`docs/design-review.md §4`](../docs/design-review.md) for the full discussion (items M2–M6).

- **Order effects (M2).** The Laya sweep ran configurations in ascending thread order
  (1, 2, 4, 8, 16, 24) with n = 6 iterations each, reported as a median. Thermal drift or a
  co-tenant process is therefore confounded with thread count. The data supports order-of-magnitude
  conclusions, **not** fine-grained ones like "16 threads is 13% better than 24".
- **kev's dtype comparison is a single observation per dtype (M3).** The reported `latency_ms` comes
  from one response body per configuration. It is recorded verbatim rather than summarised. The
  *direction* of the conclusion (bf16 on CPU is pathologically slow) is reliable because the gap is
  two orders of magnitude; the exact "83×" is not a statistic.
- **`single_caller_questions_per_second` is not throughput (M4).** It is
  `1000 / (p50_ms / n_questions)` — the rate one serial caller achieves. It ignores concurrency and,
  critically, it does not exercise cross-request batching. The field was renamed from
  `questions_per_second` because the old name invited exactly that misreading.
- These are **single-host, single-process** measurements taken before the Decis server existed. They
  measure the *engines*, not Decis.
- The Laya numbers are **within-request** batching only. Cross-request batching — the thing
  `docs/design.md §6` claims is the main throughput lever — is **not** measured here (M5). This is
  the single largest unverified assumption in the design.
- **No GPU numbers exist (M6).** `docs/feasibility.md §5` R1 tracks what still needs verifying on
  CUDA. No GPU figure may be quoted anywhere until then.
- Once `src/decis/` exists, this directory is populated by `decis bench` and the tables in the docs
  are generated by `benchmarks/report.py`, which asserts that every configuration it compares
  processed identical input hashes and token counts.
